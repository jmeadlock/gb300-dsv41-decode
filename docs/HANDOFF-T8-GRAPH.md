# HANDOFF — T8: one CUDA graph per decode step (bit-identical to the reference)

Coding worker for GB300 DSV4.1 Decode. **The spec is `docs/T8-T9A-DESIGN.md` §2 (tables 2.1–2.4) — read it in full first**, then `docs/STEP-ANATOMY-M0-20261106.md` (why: 20,550 launches/step, 109 ms GPU of 405), `bench/moe_static_spike.py` (the measured, bit-identical static-MoE pattern you must reuse: device gate → sort ids ascending → Triton pointer-table gather into static staging → fixed-k `Expert` evals → fp32 slot-order sum → + shared), `runtime/generate.py` (`prefill`/`step`/`greedy`, the digest instrument, `arm_profile`), `runtime/expert_pool.py` (pool layout, `loc` table, hot/cold views — build the per-layer pointer tables from these), `runtime/loader.py`, `runtime/patches.py` (the monkeypatch convention: cite `model.py:line`, flag-gated, default off), and the reference `model.py` lines the design table cites. `PROJECT.md` decisions 3, 9, 14.

## Deliverables (write only under `runtime/`, `bench/`, `tests/`)

1. `runtime/static_step.py` — `StaticStep(model, pool, *, max_pos)`: the fixed-shape decode step for 1 row. Implements every row of design table 2.1 (#1–#15) as a replacement that keeps the arithmetic identical: device `tok[1,1]`/`pos[1]` scalars; `index_copy_` KV/ring/compressor writes at device positions; device window indices in the **same order** as `get_window_topk_idxs` (#6); full-length compressed-KV `cat` stopgap and fixed-width topk with −inf masking (#8–#11); the two parity variants (#12: ratio-2 compressors pool only on even `pos+1`) as two code paths selected by a Python bool at build time; the static MoE (#14) as a `MoE.forward` replacement installed through `runtime/patches.py` (`static_moe(enable)`), pointer tables built once per layer from `expert_pool` (hot → HBM slot address, cold → UVA host address). `forward_static(parity)` runs the whole step eagerly from the static buffers (graph off); `capture()` warms up 2× per parity on a side stream then captures `g_even`/`g_odd` with a shared mempool; `replay(pos)` picks the graph by parity, replays, and returns the static logits buffer. Fills off at capture (`fill_uninitialized_memory=False`) and the design's L2 check run with both.
2. `runtime/generate.py` — `Generator` gains `mode="eager"|"static"|"graph"`: `step()` dispatches to the reference call, `forward_static`, or `replay`; `greedy` unchanged in output format so `bench/parity.py` and the digests work as-is. A `--marker` per-step marker kernel (a 1-thread Triton no-op with a fixed name) so nsys can find step boundaries after replay.
3. `bench/first_light.py` — `--mode` flag; `--parity-levels` runs the design's **L0** (static-eager vs reference-eager digests, 32 steps × 8 prompts), **L1** (graph vs static-eager), **L2** (replay twice + relaunch, fills on and off) and prints a table; the step cell runs in whichever mode is selected.
4. `tests/test_static_cpu.py` — Mac CPU tests of the pure index math against the reference's host functions (`get_window_topk_idxs` for pos 1…4,096, the padded-vs-dynamic topk equivalence on synthetic scores with ties handled as the design argues, parity selection), using `runtime/refmodel.import_reference(cpu_stubs=True)`; run with `.venv/bin/python -m pytest -q tests/`.
5. `tests/gpu/test_static_mini_gpu.py` — on the mini checkpoint: static-eager == reference-eager `torch.equal` logits over 10 steps; graph replay == static-eager; both parities exercised; same docker line convention as `tests/gpu/test_generate_mini_gpu.py`'s docstring. The orchestrator runs it on the box, then first light in `--mode graph`.

## Gates (the orchestrator measures; you make them measurable)
- L0/L1/L2 all equal over 32 steps × 8 prompts (fp32-logit sha256), with fills on and off.
- `bench/parity.py` on `--mode graph` output: same as first light (2/8 identical, ≤ 0.05 nats) — nothing in T8 may move a logit.
- Step cell in `--mode graph` **≤ 110 ms/step** at 1 row (design estimate ~75–110).
