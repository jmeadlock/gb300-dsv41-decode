# HANDOFF — T9b-1: a bandwidth-bound MXFP8 GEMV for the model's fp8 Linear layers at M ≤ 8, plus the glue audit

Coding worker for GB300 DSV4.1 Decode. State: the 1-row decode step is one CUDA graph at **44.6 ms** (`docs/T9A1-RESULT-20261106.md`). By the eager anatomy (`docs/STEP-ANATOMY-M0-20261106.md`), the biggest remaining items are (a) **290 reference `fp8_gemm` launches/step ≈ 16 ms** — every `Linear` with an fp8 weight: attention `wq_a/wq_b/wkv/wo_a…/wo_b`, indexer `wq_b/wk`, compressors, shared experts `w1/w3/w2`, Engram `wkv`/projections, mHC pre-GEMMs — each 44–83 µs at M=1 while the weight bytes (0.6–150 MB) would stream in 0.1–20 µs at HBM bandwidth; (b) **~11,570 one-microsecond elementwise launches/step ≈ 12 ms** of torch glue. Measured dead end: DeepGEMM `fp8_gemm_nt` on these shapes is only 1.3–1.8× faster (`docs/T9A-DEEPGEMM-ABI-20261106.md` addendum) — tile GEMMs don't help at M=1.

Read first: `reference/deepseek-inference/kernel.py:207-307` (`fp8_gemm`: block-32 scales on both operands, fp32 accumulate per K-block in K order, bf16 output), `kernel.py:40-124` (`act_quant`), `model.py:170-245` (`Linear`, `linear()`: which dtype paths exist — bf16, fp8/32 e8m0, fp8 with fp32 scales for `wo_a`?, and the `dtype=torch.float32` linears for compressors/head), `docs/checkpoint-1017-inventory.json` (shapes: `attention`, `shared_experts`, `engram`, `indexer`, `norm_mhc`, `embed_head` roles), `runtime/static_step.py` (`_linear_view`, how T8 wraps Linear views; where a GEMV would be substituted), `runtime/dg_moe.py` (the pattern for an alternative impl selected by flag), `docs/T8-T9A-DESIGN.md` §2.4 (the parity instrument), `bench/first_light.py` (`--parity-levels`, step cell).

## Deliverables (only under `runtime/`, `bench/`, `tests/`)
1. `runtime/gemv_mxfp8.py` — Triton kernel `mxfp8_gemv(xq, xs, w, s, out)` for `M ≤ 8` rows: `xq` fp8 `[M,K]`, `xs` e8m0 `[M,K/32]`, `w` fp8 `[N,K]`, `s` e8m0 `[N/32,K/32]` (the checkpoint's 32×32 blocks — index it directly, no expansion), bf16 out `[M,N]`. One program per (row-tile of N, all M); each program streams its weight rows once (vectorized 16-B loads, K-major), computes per-32-block fp32 partials and accumulates **in K-block order**, applying `exp2(sa+sb−254)` per block (e8m0 adds, exact). Autotune only over tile-N/num_warps/stages; cache the choice per (N,K). Target: ≥ 3 TB/s effective weight bandwidth on the big shapes (≥ 8 TB/s HBM here); report achieved GB/s per shape.
2. `runtime/patches.py` — `fp8_linear_gemv(enable)` monkeypatch of `model.linear()`'s fp8/e8m0 path (cite `model.py:line`) that routes to the GEMV when `x.size(0) ≤ 8` and the weight is fp8 with e8m0 scales, else falls through to `fp8_gemm`. Flag `--fp8-impl {ref,gemv}` threaded through `StaticStep`/`Generator`/`first_light` like `--moe-impl`. Must be graph-capturable (no host sync, static shapes).
3. `bench/gemv_bench.py` — box microbench on real weights (same loading pattern as `bench/dg_fp8_spike.py`): for each distinct fp8 Linear shape in the model (enumerate from the inventory), GEMV vs reference `fp8_gemm` at M=1 and M=6: µs, GB/s, bf16 mismatch rate, max |Δ|; writes `scratch/gemv-bench.json`. Correctness reference = the reference kernel; drift must be in the 1-ulp class (≤ 0.5 % of outputs); say if any shape is worse.
4. **Glue audit** (desk part, no code): `docs/GLUE-AUDIT.md` — walk the decode path (`model.py` `Block`, `Attention`, `Indexer`, `Compressor`, `Engram`, `MoE`, `hc_*`) and list every torch elementwise/reduction op per layer at 1 row with its launch count per step (from source; cross-check against the anatomy's 11,570), grouped into fusable clusters (e.g. "RoPE + in-place QDQ + cache write", "clamp/silu/mul in the shared expert", "mHC pre/post mixes", "indexer score + topk masks") with the estimated launches saved and the bit-identity risk of each fusion. Rank by launches saved. This is the T9b-2 plan; don't implement it.
5. Tests: `tests/test_gemv_cpu.py` (Mac: the e8m0 scale arithmetic `exp2(sa+sb−254)` vs float products on all code pairs; block indexing math; flag plumbing); `tests/gpu/test_gemv_gpu.py` (box: GEMV vs reference on synthetic fp8 weights across the model's shapes incl. non-multiple-of-tile N; graph capture + replay equal; the mini checkpoint step with `--fp8-impl gemv` self-replay equal and top-1 stream equal to `ref`).
