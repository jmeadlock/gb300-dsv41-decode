# HANDOFF — T2+T3: streaming loader with tiered placement, and the host tier (Engram + cold experts)

Coding worker for the GB300 DSV4.1 Megakernel project. Read `PROJECT.md` (decisions 3, 4, 9, 13, 14), then `docs/M0-PORT-PLAN.md` §2, §3, §4, §5(b)(c), §8 risks 4 and 7, then `docs/ENVIRONMENT.md`, then `docs/checkpoint-1017-inventory.json`, `reference/deepseek-inference/convert.py` + `model.py` (classes `Linear`, `ParallelEngramEmbedding`, `Expert`, `MoE`, `Transformer`, `load_model` in `generate.py`).

Goal: `runtime/` Python package that builds DeepSeek's reference `Transformer` (unchanged `model.py` imported from `reference/deepseek-inference/`) at MP=1 on one GPU, with **weights streamed from the HF shards straight into their tier**:
- HBM: everything except the two tiers below (and except vision + MTP, which are not loaded at M0);
- **pinned Grace host memory, CUDA-visible by UVA**: the two Engram tables (`layers.{1,14}.engram.embed.{weight,scale}`, 189 GiB) and the **cold experts** (a per-layer list; default map = `rowmap-static-v1`-style hot/cold split, 295 hot / 89 cold per layer; for M0 the map file is a JSON `{layer: [hot_expert_ids...]}`, and a `--hot-per-layer N` fallback that takes the first N ids).

## Deliverables (write only under `runtime/` and `tests/`)
1. `runtime/ckpt.py` — shard index: scan safetensors headers once (see `runtime/tools/ckpt_inventory.py`), `convert.py`'s rename map (`model.`→``, `self_attn`→`attn`, `mlp`→`ffn`, `weight_scale_inv`→`scale`, `e_score_correction_bias`→`bias`; **verify these against `convert.py` lines, do not trust this list**), and a `read_tensor_into(name, dst_buffer)` that reads bytes with `readinto` and `os.posix_fadvise(..., POSIX_FADV_DONTNEED)` (no page-cache doubling — the host is 494 GiB with no swap and the pinned set will be ~251 GiB).
2. `runtime/placement.py` — the placement plan: a function from (tensor name, shape, dtype, config, map) → `Tier.HBM | Tier.HOST | Tier.SKIP`, plus a dry-run report (bytes per tier per role) that must reproduce `docs/M0-PORT-PLAN.md` §4's table to within rounding (HBM experts 206.61 GiB at 295/layer, host experts 62.33, Engram 188.83). The report is a CLI: `python -m runtime.placement --model-dir D --map M` — CPU-only, runs on the shard headers.
3. `runtime/host_tier.py` — exact-size host allocations (NOT torch `pin_memory=True`: its caching allocator rounds; use `mmap.mmap(-1, n)` anonymous or `numpy.empty` + `madvise` hugepages if available), `cudaHostRegister` via `torch.cuda.cudart().cudaHostRegister(ptr, nbytes, flags)` in ≤ 64 GiB chunks with rollback (pattern: vLLM's `pin_mmap_region`, described in the plan — do not import vllm), and a CUDA-side view of the same memory **without vLLM's `_C.get_cuda_view_from_cpu_tensor`**: build it from `__cuda_array_interface__` (`torch.as_tensor(obj, device="cuda")` on an object exposing `{"shape","typestr":"|u1","data":(ptr,False),"version":3}`) and `.view(fp8 dtype)` — under UVA the registered host address is the device address. Include `release()` (unregister) and a `MemAvailable` assert before/after pinning.
4. `runtime/loader.py` — `build_and_load(model_dir, map, device) -> Transformer`: construct the reference `Transformer` with a **config overlay** (`vision_n_layers=0`, `dspark_block_size=0`, `dspark_target_layer_ids=()`, `max_batch_size=1`, `max_seq_len=32768`) **without allocating the big tensors on the GPU first** (the reference OOMs at layer 14's Engram during construction — plan §3). Use `torch.device("meta")` for construction, then materialize each parameter in its tier: HBM params via `torch.empty` on cuda + `read_tensor_into` through a pinned staging buffer; host-tier params by reading straight into the registered host buffer and assigning the CUDA view. Apply `convert.py`'s `wo_a` FP8×E8M0→bf16 dequant exactly (CPU, same formula). Expert weights: `I8 [N,K/2]` viewed as `float4_e2m1fn_x2` — zero-copy view. `Linear.weight.scale` attribute must be set as the reference expects. Refuse on any missing or unexpected key (print both lists).
5. `runtime/expert_pool.py` — hot experts in per-layer contiguous HBM slot pools (`[H, N, K/2]` + `[H, N, K/32]` per w1/w2/w3), cold experts in one registered host pool with the same layout, a device `loc[40][384]` int32 table (slot id, tier). `Expert.forward` must stay the reference's: give each `Expert` module weight **views** into the pools (hot → HBM slice, cold → CUDA view of the host slice). That is M0a's "zero-copy arm" (plan §5c). Add a per-layer cold-hit counter hook (cheap, host-side at M0a).
6. `tests/test_loader_mini.py` — a **synthetic mini checkpoint** generator (2 layers, dim 256, 8 experts, Engram tables of 1,000 rows, same tensor names/dtypes/packing as the real one, written as 2 safetensors shards) and tests that run on **CPU on the Mac** (`.venv/bin/python -m pytest tests/`; `.venv` has torch 2.8 CPU + safetensors): rename map round-trip, placement report sums, `read_tensor_into` byte-exactness (sha256 of placed bytes == shard bytes for every tensor), `wo_a` dequant vs a straightforward torch computation, fp4 view shape. GPU-only parts (`cudaHostRegister`, CUDA view, `torch.equal` of a host-tier gather vs an HBM copy on 10⁶ random ids, expert-pool views feeding the reference `fp4_gemm`) go in `tests/gpu/test_host_tier_gpu.py`, **skipped on the Mac**, written to run inside the box's library image (`vllm/vllm-openai:v0.31.0`, GB300 CDI device in `docs/ENVIRONMENT.md`) — the orchestrator runs them; write the exact `docker run` line in the test's docstring.
7. `runtime/README.md` — how to run the placement dry-run, the Mac tests, and the GPU tests; the memory numbers the dry-run printed on the real inventory (the orchestrator will paste real output; you print the synthetic one).

## Rules
- No ssh, no docker, no network, nothing outside `runtime/` and `tests/`, no git commit. The real shards are not on this machine; the inventory JSON is.
- Never import `vllm`. Only import the reference `model.py`/`kernel.py` (they import `tilelang`, which is not on the Mac: guard the import so CPU tests of `ckpt.py`/`placement.py`/`host_tier.py`'s pure parts run without it; put `tilelang`-dependent code behind a lazy import).
- Bit-identity is a design rule: no dtype conversions except the documented `wo_a` dequant; every placed tensor's bytes are hashed against the shard bytes in a `--verify` mode of the loader.
- Do not invent sizes: compute from the inventory and config; print them.
- Keep the reference `model.py` untouched. If a change to it is unavoidable, write it as a monkeypatch in `runtime/patches.py` with a comment citing `model.py:line` and why.
- Final summary ≤ 15 lines: files written, test results on the Mac (`pytest -q` output), the synthetic placement report, and what the orchestrator must run on the box (exact commands). End with `T2T3: <ready-for-box|blocked> — <reason>`.
